2.2 详细步骤说明

步骤 1：用户登录

前端操作：

  1. 用户在 /login 页面输入用户名和密码
  2. 点击"登录"按钮

API 调用：

POST /api/auth/login
Content-Type: application/json

{
  "username": "alice@example.com",
  "password": "example-password"
}

前端处理：

  • 将 accessToken 存储在内存状态（不存 localStorage/sessionStorage）
  • 将 refreshToken 作为 HttpOnly Cookie 由后端设置
  • 跳转到会议列表页 /meetings

步骤 2：创建会议

前端操作：

  1. 用户点击"创建会议"按钮，进入 /meetings/new 页面
  2. 填写会议信息：标题、预定开始时间、安全等级、参会人员
  3. 点击"创建"按钮

响应示例：

{
  "success": true,
  "data": {
    "meetingId": "m_001",
    "tenantId": "t_001",
    "title": "方案评审会",
    "securityLevel": "INTERNAL",
    "status": "CREATED",
    "transcriptVersion": 0,
    "minutesVersion": 0,
    "createdAt": "2026-05-11T06:30:00Z"
  }
}

步骤 3：上传音频

前端操作：

  1. 用户选择音频文件（最大 4 小时，约 3GB）
  2. 前端计算文件 SHA256
  3. 发起分片上传流程（初始化 → 上传分片 → 完成）

步骤 4：创建处理任务

后端处理（meeting-api）：

  1. 创建任务记录 - 插入 processing_tasks 表，状态：PENDING
  2. 写入 Outbox - 插入 domain_events_outbox 表
  3. Outbox Publisher 异步处理 - 扫描并投递到 RabbitMQ

RabbitMQ 消息体示例：

{
  "taskId": "task_001",
  "taskType": "MEETING_FULL_PIPELINE",
  "tenantId": "t_001",
  "meetingId": "m_001",
  "audioFileId": "file_001",
  "audioUri": "oss://meeting-audio/tenant/t_001/meeting/m_001/raw/file_001.wav",
  "securityLevel": "INTERNAL",
  "attemptNo": 1,
  "language": "zh",
  "knownParticipants": ["person_001", "person_002"]
}

步骤 5：Worker 处理（ai-worker）

处理步骤：

  • AUDIO_PREPROCESS 音频预处理（标准化为 16kHz mono WAV）
  • ASR 语音识别（Qwen3-ASR 模型）
  • DIARIZATION 说话人分离（pyannote.audio）
  • SPEAKER_EMBEDDING 声纹提取（3D-Speaker CAM++，192维向量）
  • SPEAKER_MATCHING 声纹匹配（余弦相似度 > 0.85）
  • TRANSCRIPT_MERGE 转录合并
  • RAG_INDEXING 知识入库（bge-m3，1024维向量）

步骤 6：Java LLM Phase

触发机制： Java WORKER_PHASE_COMPLETED outbox listener 消费事件后

  1. SUMMARY 生成纪要（调用 DashScope Qwen）
  2. EXTRACTION 抽取事项（待办、决策、风险）

步骤 7：用户查看结果

  • 📄 转录 - 时间轴式查看，可编辑
  • 📋 纪要 - Markdown 渲染，带 evidence 链接
  • ✅ 待办事项 - 接受/拒绝 AI 建议
  • 🤖 RAG 问答 - 基于会议知识库的智能问答
  • 📦 导出 - PDF/DOCX/Markdown 格式

3. 状态机定义

3.1 Processing Task 状态机

stateDiagram-v2 [*] --> PENDING: 创建任务 PENDING --> QUEUED: Outbox 发布成功 QUEUED --> RUNNING: Worker claim lease RUNNING --> SUCCEEDED: 所有必做步骤完成 RUNNING --> PARTIAL_SUCCEEDED: 可选步骤失败但有可用产物 RUNNING --> FAILED: 重试耗尽 RUNNING --> ORPHANED: Lease 过期 RUNNING --> CANCEL_PENDING: 用户取消 ORPHANED --> QUEUED: 允许重入队 ORPHANED --> FAILED: 重试耗尽 PENDING --> CANCEL_PENDING: 用户取消 QUEUED --> CANCEL_PENDING: 用户取消 CANCEL_PENDING --> CANCELLED: Worker 确认或 lease 过期 PARTIAL_SUCCEEDED --> QUEUED: 重试失败的可选步骤 FAILED --> QUEUED: 手动重试 SUCCEEDED --> [*] PARTIAL_SUCCEEDED --> [*] FAILED --> [*] CANCELLED --> [*]
状态 含义 可转换目标
PENDING 任务已创建，等待 outbox 发布 QUEUED, CANCEL_PENDING
QUEUED 已发布到 RabbitMQ，等待 worker 领取 RUNNING, CANCEL_PENDING
RUNNING Worker 已 claim lease，正在处理 SUCCEEDED, PARTIAL_SUCCEEDED, FAILED, ORPHANED, CANCEL_PENDING
ORPHANED Lease 过期，等待重入队或失败 QUEUED, FAILED
SUCCEEDED 所有必做步骤成功完成 终态
FAILED 重试耗尽或致命错误 QUEUED (手动重试), 终态

3.2 Task Phase 状态机

stateDiagram-v2 [*] --> WORKER_DAG_RUNNING: 任务开始 WORKER_DAG_RUNNING --> WORKER_DAG_DONE: Worker complete callback WORKER_DAG_DONE --> JAVA_LLM_RUNNING: Java listener 启动 SUMMARY JAVA_LLM_RUNNING --> TERMINAL: SUMMARY+EXTRACTION 完成 TERMINAL --> [*]
Phase 负责方 包含步骤
WORKER_DAG_RUNNING ai-worker AUDIO_PREPROCESS, ASR, DIARIZATION, SPEAKER_EMBEDDING, SPEAKER_MATCHING, TRANSCRIPT_MERGE, RAG_INDEXING
WORKER_DAG_DONE Java（过渡） Worker 完成，等待 Java LLM
JAVA_LLM_RUNNING Java SUMMARY, EXTRACTION
TERMINAL Java（终态） 任务完成

3.3 Processing Step 状态机

stateDiagram-v2 [*] --> PENDING: Step 创建 PENDING --> RUNNING: Worker 开始处理 RUNNING --> SUCCEEDED: 处理成功 RUNNING --> FAILED: 处理失败 RUNNING --> SKIPPED: 非必需步骤跳过 FAILED --> RUNNING: 重试 FAILED --> [*]: 重试耗尽 SUCCEEDED --> [*] SKIPPED --> [*]

3.4 Stale Status 状态机

stateDiagram-v2 [*] --> ACTIVE: 内容生成 ACTIVE --> STALE: 上游版本变化 STALE --> REBUILD_QUEUED: 请求重建 REBUILD_QUEUED --> REBUILDING: Worker claim REBUILDING --> VALIDATING: 产物回写 VALIDATING --> ACTIVE: 校验通过 VALIDATING --> FAILED: 校验失败 REBUILDING --> FAILED: 重建失败 FAILED --> REBUILD_QUEUED: 重试 ACTIVE --> DELETED: 删除任务 STALE --> DELETED: 删除任务 REBUILD_QUEUED --> DELETED: 删除任务 REBUILDING --> DELETED: 删除任务 VALIDATING --> DELETED: 删除任务 FAILED --> DELETED: 删除任务 DELETED --> [*]

触发 STALE 的场景：

  • 转录编辑 → 纪要、待办、决策、风险、RAG chunks 标记 STALE
  • Speaker 确认/拒绝 → 相关 RAG chunks 标记 STALE
  • 声纹授权撤销 → 历史 person_id 软屏蔽，RAG chunks 标记 STALE
  • Chunk 策略版本变更 → 旧策略 chunks 标记 STALE

3.5 Meeting 状态机

stateDiagram-v2 [*] --> CREATED: 创建会议 CREATED --> UPLOADED: 音频上传完成 UPLOADED --> PROCESSING: 创建处理任务 PROCESSING --> SUCCEEDED: 任务成功 PROCESSING --> FAILED: 任务失败 SUCCEEDED --> DELETED: 删除会议 FAILED --> DELETED: 删除会议 PROCESSING --> DELETED: 删除会议 DELETED --> [*]

5. 前端交互详解

5.1 登录页 (/login)

页面元素：

  • 用户名输入框
  • 密码输入框
  • "登录"按钮
  • 错误提示区域

用户操作流程：

  1. 用户在浏览器访问 http://localhost:5173/login
  2. 输入用户名（如 alice@example.com）
  3. 输入密码
  4. 点击"登录"按钮

错误处理：

  • AUTH_REQUIRED (401) → "用户名或密码错误"
  • ACCOUNT_LOCKED (423) → "账号已锁定"
  • 网络错误 → "登录失败，请稍后重试"

成功后跳转： 跳转到会议列表页 /meetings

5.2 会议列表页 (/meetings)

页面元素：

  • 顶部导航栏（用户头像、退出）
  • "创建会议"按钮
  • 搜索框（按标题搜索）
  • 筛选器：状态（全部/进行中/已完成/失败）、安全等级
  • 会议列表（虚拟滚动）- 每项显示：标题、时间、状态、参会人数、操作按钮

用户操作：

  1. 点击"创建会议" → 跳转到 /meetings/new
  2. 点击会议项 → 跳转到 /meetings/{id}
  3. 使用搜索/筛选 → 重新加载列表

5.3 创建会议页 (/meetings/new)

页面元素：

  • 会议标题输入框
  • 预定时间选择器（datetime-local）
  • 安全等级选择器：PUBLIC、INTERNAL、CONFIDENTIAL（灰色）、SECRET（灰色）
  • 参会人选择器（多选）
  • "取消"按钮、"创建"按钮

创建成功后： 显示成功提示，跳转到音频上传页 /meetings/{id}/audio

6. 关键技术点

6.1 安全与权限

Token 管理

Token 类型 存储位置 有效期 用途
Access Token 内存（Zustand store） 60 分钟 API 请求认证
Refresh Token HttpOnly Cookie 30 天 刷新 access token

为什么不用 localStorage？

  • 防止 XSS 攻击窃取 token
  • 内存存储在页面关闭后自动清除
  • 符合安全最佳实践

租户隔离（RLS）

数据库层面： 所有租户表启用 Row Level Security (RLS)，策略自动过滤数据

ALTER TABLE meetings ENABLE ROW LEVEL SECURITY;
ALTER TABLE meetings FORCE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation_meetings ON meetings
USING (tenant_id = current_setting('app.tenant_id', true)::text);

应用层面： 每个请求开始时设置租户上下文，连接归还前重置

验证： 即使 SQL 漏写 WHERE tenant_id = ?，RLS 也会自动过滤，防御 SQL 注入等安全问题

声纹数据加密

KMS 信封加密流程：

  1. ai-worker 回写明文 embedding（192 维向量）
  2. Java 调用 KMS 生成 Data Key
  3. 使用 Data Key 加密 embedding（AES/GCM）
  4. 清零明文 key
  5. 只保存密文到数据库（ciphertext + nonce + tag + wrapped_key）

为什么这样做？

  • 数据库 dump 不包含明文向量
  • DBA 无法直接读取 embedding
  • 即使数据泄露也需要 KMS 权限才能解密
  • 符合数据安全合规要求

6.2 幂等性保证

API 幂等

客户端： 写操作自动生成幂等键 Idempotency-Key

服务端： 查询缓存 → 相同 key + 相同 body hash → 返回缓存响应；相同 key + 不同 body → 409 冲突

Callback 幂等

Idempotency-Key 格式： {taskId}:{stepName}:{attemptNo}:{payloadVersion}

示例：task_001:ASR:1:v1 - 第一次报告 ASR 状态

服务端处理： 查询历史 callback → 完全相同 → 返回缓存响应；Key 相同但 body 不同 → 409 冲突

6.3 Outbox 模式

为什么需要 Outbox？

问题场景： 先写数据库再发消息，如果发消息失败，数据库已提交但消息未发送 → 数据不一致

Outbox 解决方案：

  1. 在同一事务中写业务数据 + 写 outbox 事件
  2. 后台线程扫描 outbox（SELECT ... FOR UPDATE SKIP LOCKED）
  3. 发送到 RabbitMQ
  4. 标记已发布

关键点：

  • FOR UPDATE SKIP LOCKED - 多个 publisher 实例并发扫描，跳过已锁定行
  • 同一聚合内按 sequence_no 顺序发布
  • 失败重试，重试耗尽进入 DLQ
  • 已发布事件保留 90 天供审计

6.4 Lease 机制与 Worker 心跳

Worker Lease 生命周期

Worker claim lease ↓ 设置 lease_owner 和 lease_expires_at ↓ 每 20 秒发送 heartbeat ↓ 更新 heartbeat_at 和 lease_expires_at ↓ 处理完成 → 释放 lease

Lease 过期扫描： Java 后台任务每 30 秒扫描过期任务，标记 ORPHANED，重新入队或标记失败

6.5 STALE 机制与重建

STALE 触发场景

  • 转录编辑 → 纪要、待办、决策、风险、RAG chunks 标记 STALE
  • Speaker 确认/拒绝 → 相关 RAG chunks 标记 STALE

版本冲突处理： 用户编辑转录后触发重建，重建进行中用户又编辑了转录 → 重建完成时检查版本，版本不匹配则不覆盖当前 ACTIVE

6.6 性能优化

虚拟滚动

问题： 转录可能有数千个 segment，全部渲染会导致页面卡顿

解决： 使用 react-window 虚拟滚动，只渲染可见区域 + 上下缓冲区的项

效果： 支持数千条数据流畅滚动，内存占用恒定

RAG 检索优化

pgvector HNSW 索引：

CREATE INDEX idx_knowledge_chunks_embedding ON knowledge_chunks
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

SET hnsw.ef_search = 80;

参数说明：

  • m = 16 - 每个节点连接数（越大召回率越高，但索引越大）
  • ef_construction = 64 - 构建时搜索宽度
  • ef_search = 80 - 查询时搜索宽度（越大召回率越高，但越慢）

查询性能： 10 万 chunk ~50ms，100 万 chunk ~200ms

前端 Bundle 优化

目标： 首屏 JS gzip < 200KB

措施：

  • 路由级代码分割 - 使用 Vite manualChunks 配置
  • 动态导入 - 使用 React.lazy() 延迟加载页面组件
  • Tree Shaking - 只导入需要的函数，避免导入整个库
