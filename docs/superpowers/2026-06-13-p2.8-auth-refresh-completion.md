## Implementation Overview

### Security Architecture

1. **Refresh Token Storage**
   - 30-day TTL refresh tokens stored in PostgreSQL `refresh_tokens` table
   - HttpOnly cookie prevents JavaScript access (XSS protection)
   - RLS policies enforce tenant isolation
   - Tokens revoked on logout or expiry

2. **CSRF Protection**
   - Double-submit cookie pattern
   - `XSRF-TOKEN` cookie (accessible to JS) + `X-CSRF-Token` header must match
   - CSRF token rotated on each refresh for additional security

3. **Access Token Refresh Flow**
   - Client sends refresh token (HttpOnly cookie) + CSRF token
   - Server validates both tokens and issues new 8-hour access token
   - New CSRF token returned in Set-Cookie header

## API Contract

### POST /api/auth/login
**Response Headers:**
- `Set-Cookie: REFRESH_TOKEN=<token>; HttpOnly; Secure; Path=/api/auth; Max-Age=2592000`
- `Set-Cookie: XSRF-TOKEN=<token>; Secure; Path=/api; Max-Age=2592000`

### POST /api/auth/refresh
**Request:**
- Cookie: `REFRESH_TOKEN=<token>`
- Cookie: `XSRF-TOKEN=<token>`
- Header: `X-CSRF-Token: <token>` (must match XSRF-TOKEN cookie)

**Response (200):**
```json
{
  "success": true,
  "data": {
    "accessToken": "eyJ...",
    "expiresAt": "2026-06-13T19:00:00Z"
  },
  "error": null,
  "requestId": "req_123",
  "traceId": "trace_456"
}
```
**Response Headers:**
- `Set-Cookie: XSRF-TOKEN=<new-token>; Secure; Path=/api; Max-Age=2592000`

**Error Responses (401):**
- `REFRESH_TOKEN_INVALID`: Missing or expired refresh token
- `CSRF_TOKEN_INVALID`: Missing or mismatched CSRF tokens

### POST /api/auth/logout
**Effect:**
- Revokes all refresh tokens for the user
- Clears both cookies (REFRESH_TOKEN and XSRF-TOKEN)
